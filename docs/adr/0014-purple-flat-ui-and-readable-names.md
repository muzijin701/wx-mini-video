# 紫色现代扁平化界面、业务域名提示与可读资源命名

状态：已实施（2026-11-26）。修订 [ADR 0011](0011-single-main-surface-ui.md)（视觉风格、图标来源与去自绘化、全界面扁平按钮与小程序可读提示）与 [ADR 0012](0012-per-appid-download-layout.md)（带真实资源标题的落盘文件命名）。

## 背景

1. 现行 v0.2.0 绿系色板与 3 行 ASCII 线框按钮在实机截图中暴露出多处显示缺陷与空间浪费：
   - **外观下拉**选项因设置 `Padding(0, 1)` 而比面板内宽多出 2 列，右边框 `│` 被顶出面板之外。
   - 深色模式下带边框的按钮、输入框未设置 `BorderBackground`，以及按钮/页签间拼接无样式空格，导致边框外围透出终端默认底色。
   - `composeOverlayRow` 在覆盖层结束处输出 `\x1b[0m`，重置了左侧原有背景色，导致覆盖层右侧出现一段终端默认底色竖条。
   - 打开日志浮层时仅调用 `painter.SetEnabled(false)`，此前绘制在终端上的 Sixel 像素未被显式清除，浮层顶部残留半截绿色图标。
   - 主区布局以 `width - 2*ContentLeft` 计算可用宽度，但绘制起始列使用了 `BrandPadX + ContentLeft`，造成内容整体明显偏右（左 10 列、右仅 2 列）。
   - 媒体视图 8 个 3 行高大按钮折行占掉 6 行高度、禁用态与普通态几乎无法区分、“更换目标 · s”在**目标条**与**操作按钮栏**重复出现，且亮色底色 `#88a28c` 偏灰暗。
2. 界面与落盘命名目前高度依赖原始 AppID、MD5/UUID 哈希和流 ID：纯 HTTPS 代理无法直接取得微信官方中文名称，但现行 JSON 标题提取仅覆盖 7 个字段，也未读取 HTTP `Content-Disposition` 或 H5 网页 `<title>`，导致大量有真实名称的资源仍显示为 `-` 或长哈希，不便于用户快速辨识。

## 决策

- **紫色 + 现代扁平化视觉体系（修订 ADR 0011）**：放弃“对齐参考项目绿色系与三行边框按钮”的视觉约定；改用高对比度紫系浅色（清爽浅薰衣草白底）与深紫暗色两套**外观模式**，同步修复上述 5 处显示问题。
- **全界面统一 1 行扁平色块按钮（修订 ADR 0011）**：**操作按钮栏**、**目标选择区**按钮、底栏“退出 · Ctrl+Q”以及确认弹窗按钮统一改为无 ASCII 外框的 1 行扁平色块按钮（主按钮高饱和紫底、次按钮淡紫底、禁用态低对比色阶）；移除**操作按钮栏**中与**目标条**重复的“更换目标”入口；保留 `110×40`、`80×24`、`60×20` 断点、悬停尺寸稳定及快捷键对等约束。
- **直接采用维护者个人紫色狸花猫圆角外框全身主标识并精简自绘代码（修订 ADR 0011）**：不再另外绘制或保留自绘图标代码，全部采用维护者既有个人标识的圆角正方形外框全身版本（`logo-primary-light.png` / `logo-primary-dark.png`），裁紧外围透明留白后分别打包为 TUI 双主题 PNG（`assets/logo-light.png` / `assets/logo-dark.png`）、Windows 7 帧 `.ico` 与 macOS `.icns`；TUI 品牌区按窗口高度自适应放大为 3–7 行（右侧标题垂直居中），并删除 `internal/tui/ui/brandmark.go` 块字符降级绘制、`build/logoprobe/` 独立原型以及原绿色 `assets/logo.png`。终端不支持真图时，**品牌区**直接使用纯文字标题。
- **小程序仅提供自动业务域名提示（修订 ADR 0011）**：只在程序层面从该 AppID 的请求流量中自动归纳常见**业务域名提示**（优先过滤微信通用基础域名），在**已发现列表**与**目标条**中辅助展示；不新增手动别名编辑或持久化功能，也不读取/解密 PC 微信本地数据；严格归属判定与 `downloads/<目标 AppID>/` **目标目录**命名规则保持不变。
- **候选资源两级展示**：
  1. 优先提取真实**资源标题**：扩充 JSON 常见中文业务标题字段（并支持向父级对象继承）、读取 HTTP `Content-Disposition` 文件名、提取 H5 页面 `<title>`、解码 URL 路径中的中文字符。
  2. 确实没有真实标题（例如纯 CDN 哈希或纯数字路径）时，列表展示语义兜底摘要与直播清晰度（如 `封面 · eastbuy.com`、`直播流 · 超清(FHD) · 7559…3600`），原始长哈希与完整 URL 留在详情抽屉查看。
- **带真实标题与域名的落盘文件命名（修订 ADR 0012）**：
  - 优先提取真实**资源标题**，其次提取 URL 路径中非乱码/非泛化占位名的可读文件名（均清洗非法字符并截断至约 40 字以内以防路径过长）；界面泛化兜底摘要（如 `MP4 视频 · eastbuy.com`）不写入文件名。
  - 普通资源（图片、**直链视频**、**直链音频**、**分段媒体**、其他）不再附加时间戳：有标题/可读文件名时为 `<短标题>_<候选ID前8位>.<后缀>`；彻底无标题时优先附加**业务域名提示** `<类型前缀>_<业务域名>_<候选ID前8位>.<后缀>`（无域名时为 `<类型前缀>_<候选ID前8位>.<后缀>`）。
  - **直播录制**（**HTTP-FLV 直播流**）：同一直播流可能反复录制多次且候选 ID 相同，因此保留时间戳：有标题时为 `<短标题>_<时间>_<候选ID前8位>.flv`，无标题时为 `直播_<业务域名>_<时间>_<候选ID前8位>.flv`（无域名时为 `直播_<时间>_<候选ID前8位>.flv`）。
  - 保留 `_<候选ID前8位>` 以兼容重名保护及普通下载 `.part` 断点续传定位；`downloads/<目标 AppID>/<资源分类目录>/` 目录布局与 `history.jsonl` 语义保持不变。

## 备选方案

- **保留绿色系与参考项目图标，仅修复错位与透底问题**：无法解决亮色偏闷、3 行按钮占据过多高度以及整体复古感问题。
- **仅将操作按钮栏改扁平，底栏“退出”与弹窗保留 3 行边框**：界面控件形态割裂，且底栏与弹窗在深色模式下仍存在边框渲染与垂直空间浪费问题。
- **增加本地小程序手动别名，或读取微信窗口标题 / 解密 `.wxapkg`**：手动别名引入额外配置与交互状态，微信本地库随客户端升级易失效且跨平台不一致；自动**业务域名提示**以零交互成本提供核心辨识线索。
- **无真实标题时直接截短哈希显示**：仍需用户从无意义字符中猜测资源用途，不如语义兜底摘要直观。
- **落盘只使用 `<名称>.<后缀>` 或直播也省略时间戳**：缺少候选 ID 前缀会破坏同候选 `.part` 续传定位，直播省略时间戳则不利于区分多次开录产物。

## 后果

- TUI 色板、样式、按钮高度与相关布局、悬停回归测试需同步更新，并验证全界面 `110×40`、`80×24`、`60×20` 尺寸下的行列宽度与命中坐标稳定。
- **品牌区** PNG 与 Windows/macOS 图标资产需同步重制，重新通过 `build/genicon` 与 `build/verify-macos.py` 校验。
- 嗅探插件与下载器需补齐标题字段扩展、HTTP 头与网页标题提取、直播清晰度解析、文件名清洗截断以及带标题文件的重名/续传回归测试。
- 实施完成后需同步更新 `README.md`、`README.en.md`、`wx-mini-video-knowledge.md`、`CHANGELOG.md` 与文档截图。
